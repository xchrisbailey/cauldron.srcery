# Domain docs

This repo has one domain context.

Before exploring or specifying domain behaviour:
- Read GLOSSARY.md and use its vocabulary.
- Read relevant decisions in docs/native/decisions.md.
- Read relevant ADRs in docs/adr/ when present.

Missing glossary or ADR files do not block work; create them lazily
when terms or architectural decisions are resolved.

Surface conflicts with existing decisions rather than silently
overriding them. Keep glossary definitions free of implementation details.
